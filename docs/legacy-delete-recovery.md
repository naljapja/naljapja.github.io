# 기존 약속의 주최자 권한 복구

관리 코드 도입 전 버전은 브라우저에 약속 ID와 제목만 저장했습니다. 이 기록으로 주최자 메뉴는 표시되지만, 서버가 확인하는 관리 코드는 없습니다. 브라우저의 기록만으로 소유권을 증명할 수 없으므로 관리 코드를 자동 발급하지 않습니다. 일반 참여자의 날짜 응답은 계속 가능합니다.

## 운영자가 처리할 일

1. Firebase Console에서 프로젝트 `yaksok-191a7`을 선택하고 대상 `events/{약속 ID}`의 제목과 생성 시점을 확인합니다. 요청자가 해당 약속의 주최자인지 별도로 확인합니다.
2. `hostkeys/{같은 약속 ID}` 문서가 없는지 확인합니다. 이미 문서가 있으면 새 문서로 덮어쓰지 말고 기존 관리 정보의 복구가 필요한지 확인합니다.
3. 관리자 계정으로 해당 약속의 주최자 권한을 발급해도 되는지 확인받은 다음, 암호학적 난수 32바이트로 만든 코드를 `key` 문자열 필드에 저장합니다. 웹 입력창은 영문 대소문자, 숫자, `_`, `-`로 구성된 20~128자 코드를 받습니다.
4. 코드를 주최자에게 비공개로 전달합니다. 코드를 가진 사람은 해당 약속의 명단·마감·확정일을 변경하거나 삭제할 수 있으므로 공개 저장소, 일반 공유 링크, PR, 로그에 넣지 않습니다.

브라우저에 코드를 저장하는 것과 서버에 권한을 발급하는 것은 별개입니다. 복구할 때 서버 보안 규칙을 바꾸거나 기존 약속의 내용·응답을 수정할 필요는 없습니다. 삭제된 약속에는 코드를 발급하지 않습니다.

## 주최자가 처리할 일

약속을 만든 브라우저에서 해당 링크를 다시 열고 **주최자 메뉴 → 관리 권한 복구**에 운영자가 전달한 코드를 입력합니다. 코드는 해당 브라우저의 해당 약속 기록에만 저장됩니다. 브라우저 저장 공간이 차단되면 입력 내용을 유지하고 오류를 표시합니다.

입력한 코드가 실제 권한과 일치하는지는 주최자 작업을 요청할 때 서버가 검사합니다. 코드가 틀리면 변경은 거부되며, **관리 권한 복구**에서 다시 입력할 수 있습니다. 복구 코드를 저장하는 동작 자체는 약속이나 응답을 지우지 않습니다.

## 검증 범위

화면 검증은 실제 Firebase와 분리된 저장소·화면 모형으로, 서버 규칙 검증은 로컬 Firestore 에뮬레이터로 실행합니다. 실제 약속을 삭제하는 테스트는 실행하지 않습니다. 운영자의 코드 발급과 주최자의 브라우저 적용은 별도로 완료해야 합니다.
